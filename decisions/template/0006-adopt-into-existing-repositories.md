# 6. 이미 운영하던 저장소에 템플릿 들이기

## 상태

채택(2026-09-26).

## 배경

템플릿의 규칙과 도구는 "Use this template" 으로 새로 만든 저장소에만 들어갑니다. 템플릿 업데이트도 `template.json` 과 구역 표시가 이미 있는 저장소에서만 동작합니다. 템플릿 없이 이미 운영하던 저장소도 같은 규칙을 쓰게 하려면, 파일이 가득한 저장소에 템플릿을 처음 들이는 길이 필요합니다.

## 결정

- `swift run repo template adopt <저장소 경로>` 는 템플릿 checkout 에서 실행하고, 그 checkout 의 작업 트리를 대상 저장소에 들입니다.
- 대상이 git 작업 트리가 아니거나, 커밋하지 않은 변경이 있거나, 이미 `template.json` 이 있으면 아무것도 쓰지 않고 멈춥니다.
- 관리 경로가 대상에 이미 있는데 내용이 다르면, 다른 경로를 모두 보여 주고 아무것도 쓰지 않고 멈춥니다. 내용이 같으면 넘어갑니다.
- 구역 표시가 없는 기존 규칙 문서(`AGENTS.md`, `ARCHITECTURE.md`)는 템플릿 구역과 주인 절 제목 아래로 그대로 옮기고, 저장소 주인에게 정리하라고 알립니다.
- `repo.json` 은 없을 때만 만들고, `.gitignore` 에는 템플릿에만 있는 줄을 더합니다. `README.md`, `LICENSE`, `apps/`, `packages/`, `bricks/` 는 건드리지 않습니다.
- 커밋하지 않고, `--dry-run` 으로 바뀔 경로를 먼저 보여 줍니다.

## 검토한 대안

- **대상 저장소에 도구를 먼저 복사하게 하기:** 기각되었습니다. 도구를 복사하는 일과 템플릿을 들이는 일의 순서가 꼬이고, 손으로 할 일이 늘어납니다.
- **충돌하는 파일을 덮어쓰기:** 기각되었습니다. 저장소 주인이 만든 파일을 잃습니다.

## 결과

- 들인 저장소는 바로 `swift run repo doctor` 와 `swift run repo template update` 를 쓸 수 있고, 같은 판으로 update 하면 이미 최신이라고 나옵니다.
- 관리 경로와 같은 이름의 파일이 있는 저장소는, 그 파일을 먼저 옮기거나 지워야 들일 수 있습니다.
- 주인 절로 옮긴 기존 규칙은 템플릿 구역의 규칙과 겹치거나 부딪힐 수 있으므로, 저장소 주인이 정리해야 합니다.
