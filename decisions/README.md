# 결정 기록

구조를 정하거나 바꾼 결정의 이유와, 검토했지만 고르지 않은 대안을 여기에 남깁니다. 동작 설명은 결정 기록이 아니라 도구의 도움말과 앱의 README 에 둡니다.

## 위치

- `decisions/NNNN-짧은-제목.md`: 이 저장소에서 내린 결정입니다. 저장소 주인의 것이며 템플릿 업데이트가 건드리지 않습니다.
- `decisions/template/`: 템플릿이 내린 결정입니다. 템플릿이 관리하므로 새 판을 받으면 함께 바뀝니다.

`NNNN` 은 0001 부터 하나씩 올리고, 파일 이름의 제목은 영문 소문자와 하이픈으로 짧게 씁니다.

## 형식

한 파일에 결정 하나를 적습니다. 기록은 더하기만 합니다. 결정이 바뀌면 이전 기록을 고치지 않고 새 기록을 만들어서, 새 기록의 상태 절에 어느 기록을 대신하는지 적습니다.

```markdown
# N. 제목

## 상태

채택, 제안, 대체됨 가운데 하나와 날짜를 적습니다.

## 배경

결정이 필요해진 상황과 제약을 적습니다.

## 결정

정한 내용을 적습니다.

## 검토한 대안

- **대안:** 기각한 이유를 적습니다.

## 결과

이 결정으로 생기는 영향과 비용을 적습니다.
```

## 예시

`decisions/0001-memo-board-storage.md`

```markdown
# 1. memo-board 의 메모를 JSON 파일에 저장

## 상태

채택(2026-10-01).

## 배경

memo-board 의 메모를 앱과 CLI 가 함께 읽고 써야 합니다. 메모는 수백 개 정도로 예상합니다.

## 결정

앱 데이터 디렉터리의 `items.json` 파일 하나에 저장하고, 쓸 때마다 파일 전체를 atomic write 합니다.

## 검토한 대안

- **SQLite:** 기각했습니다. 질의가 필요할 만큼 데이터가 크지 않습니다.
- **Core Data:** 기각했습니다. CLI 에서 같은 저장소를 다루기 번거롭습니다.

## 결과

외부 의존 없이 사람이 파일 내용을 바로 읽을 수 있습니다. 메모가 수만 개로 늘어나면 저장 방식을 다시 정해야 합니다.
```
